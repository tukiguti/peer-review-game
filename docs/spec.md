# 査読ゲーム 実装仕様

ゲームルール・カード設計・演出仕様の正本は、zikken リポジトリの
[`playground/peer-review-game-plan/`](https://github.com/tukiguti/zikken/tree/main/playground/peer-review-game-plan) に置く。
ルール変更は正本と実装を同じ変更単位で更新し、このリポジトリ内に仕様全文を複製しない。

## 実装上の不変条件

- 起動時に**オフライン/オンライン**を選ぶ。この選択はApp側のナビゲーションで、ゲーム進行のreducerとは独立。
- 3〜8人。同じ名前・空欄の名前では開始できない。
- 1人の手番は `draw → prepare（設定時のみ）→ present → vote → result` の順に進む。
- カード構成は1〜5枚。各スロットを分野・手法・制約・**新規性**から選べ、同じ種類を複数指定できる（既定は「査読4枚」＝分野・手法・制約・新規性）。
- 各スロットは独立して `all`（おまかせ）・`serious`（真面目）・`neta`（ネタ）を選べる。抽選と引き直しは対象スロットの指定を守る。
- 初回の一括抽選は1手番につき1回だけ。以降はプレイヤーごとの残り回数を消費し、1枚ずつ引き直す。
- 同種カードを複数引いても同一カードは重複させない。絞り込み後の候補が足りない構成では開始できない。
- 分野・手法・制約・新規性の4デッキは、全9ジャンル（汎用・SE・セキュリティ・情報科学・心理学・生物医学・食料理・経済社会・ファッション）と serious/neta の組み合わせで必ず1枚以上ある。ジャンルを絞っても既定構成が引けること。
- カードを足すときは、日本語以外の文字混入・文言重複・ID衝突がないことを取り込み前に検査する。
- 直近3手番に出たカードは候補から外す。ただし候補が空になる場合だけ、そのデッキを復帰させる。
- 発表者は投票しない。査読者全員の投票が揃う前に結果表示・得点加算を行わない。
- **投票方式は `voteMode` で2種**。`simultaneous`（せーの＝既定）: 準備→カウントダウン→全員同時公開→司会が各自の手を記録。`passplay`: 端末を回して1人ずつ秘密投票し、送信後は画面から消す（全員完了後だけ氏名付きで公開）。
- Accept が投票者の半数を**超えた**場合だけ採択。同数は Reject 判定とする。
- **得点は発表者だけに入る**。採択+1点、満場一致採択+2点（重複加算なし）、不採択0点。査読者への加点はしない。得点計算・結果画面は投票方式によらず共通。
- **リバッタルは不採択のときだけ、1手番に1回**。発表者の弁明（30秒）に戻り、投票をやり直す。やり直しに伴い、前の投票を査読者のAccept/Reject数から取り消してから再集計する（称号の二重計上を防ぐ）。採択済み・使用済みなら受け付けない。
- 称号は4つで、**得点と独立した軸を含める**。学会MVP（総得点）/ 話術賞（満場一致数）/ Reviewer #2 賞（Reject最多）/ オープンアクセス賞（Accept最多）。実績0件は「該当者なし」。
- 設定保存に失敗してもゲーム本体を停止させない。
- 演出オフでも、リール中央と確定カードの内容を一致させる。

## オンライン（各自スマホ）の不変条件

- **状態の権威はサーバ（Durable Object）**。クライアントは受け取ったスナップショットを描画するだけで、独自に進行しない。抽選と得点はオフラインと同じ純粋関数を使う。
- **公開前に他人の投票内容を配信しない**。voting 中に配るのは「誰が投票済みか」と「自分の投票」だけで、他人の Accept/Reject は reveal 後にのみ載せる。
- 発表者は投票しない。接続中の査読者が全員投票した時点で自動的に公開する。集計対象は実際に投票した人だけで、切断者・未投票者は母数に入れない。
- **最少3人**（過半数が成立する人数）。同じ名前では参加できない。上限8人。
- 司会だけが設定変更・開始・投票開始・締め切り・手番の放棄・次へ・再戦を行える。**サーバ側でも権限と値を検証**し、範囲外の枚数・不正なジャンル・抽選不能な構成は拒否する。
- **通信断では席を失わない**。ロビー・ゲーム中を問わず切断は `connected=false` にとどめ、本人だけが持つ token による復帰を受け付ける。席が空くのは明示的な退出のときだけで、未復帰の席は開始時に整理する。
- 復帰の認証に公開IDを使わない。token は本人にだけ送る。
- **部屋の状態は storage に保存**し、Worker の再デプロイやインスタンス再起動をまたいでも失われない。復元直後は全員 `connected=false` から始める。
- **進行不能を作らない**。査読者が全員切断しても司会が締め切れる（票0なら不採択・加点なし）。司会が切断中なら他の接続者が引き継げる。
- 復帰情報はタブ単位（`sessionStorage`）に持つ。オリジン共有の localStorage だと同一端末の別タブが互いの席を奪う。
- **不採択の理由カードはオンラインのみ**。Reject にだけ添えられ、定型の一覧にない値はサーバで捨てる。公開前は他人の理由もコメントも配信しない。
- 発表タイマーはサーバの絶対時刻で配り、受信時のオフセットで端末の時計ズレを補正する。画面復帰時に計算し直す（ブラウザは非表示中タイマーを間引くため）。締切で投票へ進めるのは司会の端末だけだが、手動ボタンが常にあるので進行不能にはならない。

## 自動テストの必須範囲

- 得点: 同数Reject、通常採択(+1)、満場一致(+2)、査読者に加点しないこと。
- 抽選: 直近カード除外、空デッキ時の復帰、ジャンル・スロット別tone絞り込み、引き直し時のtone維持。
- データ: 全カードIDの一意性、全モード組み合わせの非空性。
- 状態遷移: 無料再抽選の禁止、リロール上限、投票完了前の進行禁止、結果画面以外からの次手番禁止、8人×3周で全査読者が過不足なく投票すること。
- 投票方式: せーの方式の `ready→countdown→tally→result` 遷移、発表者が集計対象外であること、全員未入力なら結果へ進めないこと。
- 可変構成: 1〜5枚、分野×3の重複なし抽選、スロット別の真面目・ネタ混在、同種カードのリロール、絞り込み後の候補不足判定。
- 設定: 入力途中の名前を巻き戻さない、空欄・重複名で開始しない、旧全体tone設定をスロット別設定へ移行する。
- 称号: 4種をこの順で返す、最大値の持ち主に与える、同率は全員、実績0は空、得点と独立に決まること。
- リバッタル: 不採択でのみ入れる、1手番に1回、やり直しで前の投票を記録から取り消す、弁明後に採択されれば加点、次の手番で権利が戻る。
- オンライン（部屋サーバへ実接続して確認する）: 公開前に他人の投票が漏れないこと、同数が不採択になること、ゲーム中の切断からtokenで復帰できること、他人のIDでも誤ったtokenでは復帰できないこと、査読者が全滅しても司会が締め切れること、ロビーの切断で席が消えないこと、司会切断時に引き継げること、サーバ再起動後も部屋・得点・設定が残ること、2人では開始できないこと。

## 公開前チェック

```bash
npm ci
npm test
npm run build
```

続いて実ブラウザで、最低限次のシナリオを確認する。

1. 遊び方選択で**オフライン**を選び、3人・1周・準備なし・演出オフで開始する。
2. 名前を一度空にして再入力し、フォーカスが外れず、空欄中は開始できないことを確認する。
3. 設定枚数の抽選後に `LEVER` が再利用できず、1枚引き直すと残数が減ることを確認する。
4. 既定の**せーの方式**で、カウントダウン→集計→Accept 1票 / Reject 1票で不採択となり、Rejectした査読者だけ+1点になることを確認する。
5. 3人全員の手番を終え、最終ランキング・学会MVP・各称号を確認する。
6. 幅320px相当の画面でも横スクロールや操作不能がないことを確認する。
7. 同じ種類のスロットに真面目とネタを別々に設定し、抽選・引き直し後のカードがそれぞれの指定に合うことを確認する。
8. 投票方式を**パスプレイ**に切り替え、端末を回す秘密投票で、送信後に前の人の選択が画面に残らないことを確認する。
9. **オンライン**を3端末（またはタブ）で開き、部屋の作成・QRとコードでの参加・司会の設定変更が全員に反映されること、秘密投票が揃った時点で一斉公開されることを確認する。
10. オンラインの進行中に**部屋サーバを再起動**し、各端末が自動で再接続して同じ場面に戻り、そのまま投票→結果まで続けられることを確認する。
11. 不採択の結果から**リバッタル**に入り、弁明のあと投票し直して採択になると発表者に点が入ることを、オフラインとオンラインの両方で確認する。
12. オンラインで Reject に**理由カード**を選び、結果画面で票の横に出ること、Accept には付かないことを確認する。
13. ジャンルを**汎用以外**（例: 心理学）に絞って開始し、抽選が成立して同じ札が続きすぎないことを確認する。
